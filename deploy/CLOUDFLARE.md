# Посредник Cloudflare для бота

Зачем: из России Telegram не достучивается до бота на reg.ru, а запросы бота к Telegram идут медленно.
Посредник (Cloudflare Worker, бесплатно) стоит за границей и передаёт сообщения в обе стороны.

```
Клиент → Telegram → посредник (Cloudflare) → бот на reg.ru
бот на reg.ru / форма сайта → посредник (с ключом) → Telegram
```

Бесплатного тарифа хватает с запасом: 100 000 запросов в сутки, у бота — сотни.

## 1. Создать воркер (5 минут)

1. dash.cloudflare.com → слева «Compute» → «Workers & Pages».
2. Синяя кнопка «Create application».
3. Вариант «Start with Hello World!» (может называться «Create Worker»).
4. Имя (Worker name): `tg-relay` → «Deploy».
5. Откроется страница «Success». Нажмите «Edit code» (или «Continue to project» → справа вверху «Edit code» / значок «</>»).
6. Слева в редакторе открыт файл `worker.js`. Выделите весь код (Ctrl+A / Cmd+A) → удалите.
7. Вставьте целиком содержимое файла `cloudflare-worker.js` (открыть в «Блокноте»/TextEdit → выделить всё → копировать).
8. Справа вверху «Deploy» → подтвердите «Save and deploy».
9. Вернитесь назад (стрелка слева вверху). На странице воркера в блоке «Domains & Routes» (или вверху) есть адрес вида
   `https://tg-relay.ИМЯ.workers.dev` — скопируйте его.

Проверка: откройте в браузере `https://tg-relay.ИМЯ.workers.dev/health` — должна быть строка, начинающаяся с `relay ok`.
Если в России адрес не открывается — это нормально, важно, чтобы он работал с хостинга (проверит шаг 3).

## 2. Загрузить файлы на хостинг (5 минут)

1. Менеджер файлов → в строке пути нажмите «/» (домашняя папка, где видна `www`).
2. «Закачать» → `telegram-bot.zip` → «Извлечь» → «Заменить» / «Да для всех» → удалите zip.
   Токен, chat_id и база бота не затрагиваются.
3. Откройте `www/realtyminaev.ru` → «Закачать» → `lead.php` → согласиться на замену.

## 3. Подключить бота к посреднику (5 минут)

ISPmanager → «Shell-клиент». Вставьте (адрес — ваш, из шага 1.9):

    cd ~/telegram-bot && /opt/python/python-3.14/bin/python3 manage.py use-relay https://tg-relay.ИМЯ.workers.dev

Первый запуск завершится сообщением «Посредник не пропустил запрос» и строкой `RELAY_KEY = ...` — это ключ.

Добавьте ключ в Cloudflare:
1. Workers & Pages → `tg-relay` → вкладка «Settings».
2. Блок «Variables and Secrets» → «+ Add».
3. Type: **Secret**. Variable name: `RELAY_KEY`. Value: ключ из Shell (без пробелов).
4. «Deploy».

Запустите ту же команду ещё раз. Успех выглядит так:

    Посредник работает: https://tg-relay.ИМЯ.workers.dev
    Форма сайта тоже отправляет заявки через посредника.
    Вебхук установлен: https://tg-relay.ИМЯ.workers.dev/webhook
    ...
    Ожидают доставки: 0

Если «Хостинг не может связаться с посредником» — пришлите скриншот разработчику (значит, провайдер хостинга режет Cloudflare; нужен другой посредник).

## 4. Проверка

1. @RealtyMinaev_bot → `/start`: баннер, приветствие, синяя кнопка «Оставить заявку».
2. Пройдите заявку — она придёт вам.
3. Отправьте форму на сайте — заявка придёт в Telegram и на почту.
4. Через минуту в Shell: `cd ~/telegram-bot && /opt/python/python-3.14/bin/python3 manage.py check` — «Последней ошибки» быть не должно.

## Безопасность

- Ключ RELAY_KEY хранится только в Cloudflare (как Secret) и в `~/telegram-bot/.env`. Без него посредник Telegram-запросы не пропускает.
- Сообщения вебхука бот проверяет по своему секрету (WEBHOOK_SECRET), посредник их только передаёт.
- Через Cloudflare (США) проходят данные заявок — это трансграничная передача: Cloudflare нужно указать в политике, согласии и уведомлении в Роскомнадзор.

## Отключить посредника

В `~/telegram-bot/.env` удалите строки `TELEGRAM_API_BASE`, `RELAY_KEY`, верните `PUBLIC_URL=https://bot.realtyminaev.ru`,
затем `manage.py set-webhook`.
